# Phase 4(a): E4 shaped forward equilibria

Two E4 source laws, five codes, four resolutions per code: 40 completed
producer runs and 24 KIN6D/CHEASE export-to-consumer paths. This is the explicit
Miller case, distinct from TC24. VMEC++ remains above the sampled targets over
the tested radial ladder. Finite-beta DESC reaches the physical targets and
native stopping with a target-calibrated warm restart; the historical capped
outputs remain retained and identified.

The [cases](../cases.json) are generated by the shared
[case builder](../../phase2/cases.py) from the authoritative contract:
R0=6.2 m, a=2 m (A=3.1), kappa=1.7, delta=0.33, B_reference=5.3 T,
F_edge=32.86 T m, COCOS 3, psi_edge=pressure_edge=0.
The boundary is R=R0+a*cos(theta+asin(delta)*sin(theta)),
Z=kappa*a*sin(theta), sampled at 4096 uniform theta values plus closure.
Public CHEASE receives 2048 samples plus closure within its native capacity.
`E4_E1` has p'=0 and FF'=-7.066666666666666 T; `E4_E2` has FF'=0 and
p'=-146292.2647219988 Pa/(Wb/rad). The source scale 1.5 does not prescribe q.

The shared Phase 2 driver, producers, metrics, analysis, export tools and plotter
are reused. KIN6D P3 uses boundary_nodes=24,48,96,192; the finest state is the
numerical reference. CHEASE uses NS=NT=16,32,64,128. VMEC++ uses
NS=33,65,129,257 with MPOL=24, NTHETA=96, tcon0=1 and ftol=1e-16.
DESC uses L=M=6,8,10,12, maxiter=200, with M=4 continuation seeds for M>=8.
Expected field rates are at least third order for P3, bicubic convergence for
CHEASE, first order radially for VMEC++, and spectral convergence for DESC.
All solves use one pinned logical CPU (14), one numerical-library thread,
and a 300 s limit on the Ryzen 9 5950X. Consumer readback uses CPU 15.
Producer wall time includes setup, solve and native
readback; KIN6D also includes its majorant. Error-oracle evaluation is excluded.
Concurrent work on the shared host makes single-run timings indicative.

Native errors use 4000 fixed area-uniform samples with s_pol<=0.98 and volume
weights R; q uses 40 s_tor levels in [0.05,0.98]. Max field errors are normalized
by the reference maximum; q uses pointwise relative errors. The excluded shell
is not qualified. VMEC++/DESC receive reference pressure(s_tor), iota(s_tor)
and Phi_edge; their q/Phi errors measure input transfer, while physical fields
and axis remain independent outputs. No alignment or gain is fitted.

The recovered-flux majorant estimates the full represented-domain energy
sqrt(integral R*|delta Bpol|^2 dR dZ), with ordinary quadrature. Richardson
uses the interior samples. Its energy conversion uses the Miller boundary's
area (21.062232690602272 m2), so the excluded shell remains a norm difference.
The independently integrated toroidal volume is 798.7635691003494 m3.
These are numerical estimates, not interval bounds. The majorant recovery
cap defect was fixed in KIN6D `1ada383` on `lane/phase4a`;
[EQ-P4A-1](../../ERRATA.md#eq-p4a-1) owns the finding and regression evidence.
Both finest recoveries reach 6000 iterations; the functional estimates remain
valid for their finite recovered fields, with recovery status recorded.

Above-target differences have these cause classes:

- **VMEC++: radial discretization.** At NS=257, psi/Bpol L2 differences are
  3.48e-6/2.02e-5 (zero beta) and 8.58e-6/3.95e-5 (finite beta); axis errors
  are 3.67e-5 / 8.97e-5. All decrease under radial refinement. The known slower
  axis behaviour is recorded in EQ-D20; no wrong-limit defect is established.
- **DESC: spectral discretization, then stopping limit.** Zero beta passes
  the combined gate at M=8. Finite beta M=8 gives Bpol=8.96e-6, psi=1.62e-6,
  axis=1.57e-6. M=10/12 reduce these below the field targets but stop at 200
  iterations. At M=12, Bpol differences are 5.76e-8 / 8.80e-8 and psi
  differences 1.32e-8 / 1.97e-8. The original strict-tolerance outputs remain
  capped. A retained finite-beta M=12 warm restart with another 100 iterations
  at `gtol=1e-12` changes Bpol L2 by only 5.22e-9 while still hitting the cap.
  With `gtol=1e-10`, the same original state stops natively after two iterations:
  psi L2=1.97e-8, Bpol L2/max=8.79e-8/3.85e-7, Btor L2=2.66e-9,
  axis=2.23e-8 and volume=4.38e-10 against the retained KIN6D reference.
  This closes finite-beta stopping at the physical targets; no solver fix is
  needed. [Stopping controls](desc_stopping.csv) retain the exact settings,
  physical plateau and native messages. The additional 31.49 s includes cold
  JAX compilation on CPU6; it is a restart cost, not a replacement of the
  original CPU14 convergence/cost curve. Zero-beta M=10/12 remain historical
  strict-tolerance capped outputs; zero-beta already passes at M=8.
- **CHEASE and KIN6D: mesh discretization.** The measured rates and numerical
  reference estimates decrease past the targets. No further reconstruction
  or precision investigation is needed at this accuracy.

The Cerfon boundary limitation in [EQ-D20](../../ERRATA.md#eq-d20) is not
transferred to this Miller parameterization. Its relative Fourier boundary
errors are 3.21e-8, 1.61e-11, 6.24e-15 and 1.79e-15 at M=6,8,10,12,
recorded in the case CSVs. The Miller boundary is already represented much more
accurately than the field at M=6.

Reproduction uses the existing lane Python environments and producer binaries;
retained request/manifest files own all executed inputs and repeats:

```sh
python -m equilibrium.phase2.cases --group shaped --output equilibrium/phase4/cases.json
python -m equilibrium.phase2.compare --tag UNIQUE --cases E4_E1 E4_E2 \
  --case-file equilibrium/phase4/cases.json --output-dir equilibrium/phase4/results \
  --lane /home/ert/code/worktrees/_lanes/phase4a --cpu 14 --kin6d-binary "$KIN6D_BINARY"
python -m equilibrium.phase2.analyze --tag UNIQUE \
  --case-file equilibrium/phase4/cases.json --output-dir equilibrium/phase4/results
```

Use the same case/output/tag options for `equilibrium.phase2.exports` and
`equilibrium.phase2.boozer`, with the recorded KIN6D binary and reader binaries.
The latter also accepts `--lane`. Run the plotter with
`--results equilibrium/phase4/results --output DISK_DIRECTORY`, then publish
with `equilibrium.phase2.publish DISK_DIRECTORY --index equilibrium/phase4/results/artifacts.json`.
